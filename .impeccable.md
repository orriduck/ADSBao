## Design Context

This is a concise product brief. `DESIGN.md` is the visual implementation
source of truth; `PRODUCT.md` owns the product direction; `CLAUDE.md` owns
validation. When they conflict with a generic design skill, the project
documents win.

### Users

ADSBao is for aviation-focused operators, pilots, spotters, and technically
fluent enthusiasts reading an airport's live operating picture. The map stays
primary while weather, traffic, route intent, and selected-aircraft detail are
scanned quickly.

### Brand Personality

Industrial, precise, cinematic, and calm under load. It should feel like a
serious field-operations console—not generic SaaS, consumer travel polish, or
military simulation.

### Active visual system

- Soft Instrument Surfaces use rounded groups, shallow relief, fine rims and
  existing Figtree typography inside the allocated sidebar width.
- The user's sage/gray-olive/warm-ivory photograph guides UI materials. Light
  surfaces use lifted ivory; dark surfaces use olive charcoal.
- One sage accent has ink, solid inlay and wash roles: identifiers and small
  icon medallions, directory code wells, selected readings and temperature scales.
- Ordinary buttons and provider marks remain neutral. Flight-rule severity,
  loading and unavailable states must not read as brand-colored success.
- Map footprint, map styling, routes and data contracts remain unchanged.
- Reuse `src/soft-surfaces.css`. Motion is short, state-driven and respects
  reduced motion. See `docs/design/sage-color-study.md` for researched sources.

Before UI implementation, read `DESIGN.md` and inspect the affected screen in
a real browser in the relevant theme. Preserve active routes, click paths, and
map-layer semantics unless the task explicitly changes them.
